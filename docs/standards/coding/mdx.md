# MDXコーディング規約

## 配置

- 記事ファイルは`content/posts`配下へ置きます。
- ファイル名には小文字の英数字とハイフンを使用します。
- メイン画像は`public/images/posts/<記事slug>/hero.webp`へ置きます。
- メイン画像は4:3、1440×1080pxのWebPを基準とします。
- 下書きではメイン画像を省略できますが、公開記事では必須です。
- 記事から読み込むその他の画像は、記事単位で所在を追跡できる場所へ置きます。

## Frontmatter

- 記事には`title`、`description`、`publishedAt`、`category`、`tags`、`draft`、`imageAlt`を定義します。
- メイン画像のパスは記事slugから生成するため、`image`は定義しません。
- `category`は`Projects`、`AI`、`Frontend`、`Backend & Cloud`、`Design`、`Journal`のいずれか一つを指定します。
- Next.jsやAWSなどの個別技術と、「作ってみた」「備忘録」などの記事形式は`tags`で表します。
- 更新日が公開日と異なる場合は`updatedAt`を定義します。
- 日付には`YYYY-MM-DD`形式を使用します。
- Frontmatterはビルド時に検証し、必須項目の不足、未知または重複した項目、不正な値がある場合はビルドを失敗させます。
- メイン画像が存在しない場合はビルドを失敗させます。
- `draft: true`の記事を本番出力へ含めません。
- 開発サーバーでは`/posts/<記事slug>/`から下書きをプレビューできます。
- Heroには公開日の新しい記事から最大3件を表示します。

## 本文

- 執筆前に既存の公開記事を読み、著者の語り口、言葉遣い、文の長さ、段落の作り方に合わせます。
- 本文は原則として句点「。」の後で改行します。ただし、改行せずに続けた方が自然で読みやすい場合は、同じ行で続けても構いません。
- 同じ段落内の改行は、句点の後に`<br />`を置き、ソースも改行します。MDXではソース上の改行だけでは画面に反映されないため、表示上も改行されることを確認します。
- 話題が変わる箇所は空行で段落を分けます。すでに段落やリスト項目が終わる箇所に、改行目的の`<br />`を重ねません。
- 括弧などの記号で終わる語句を強調し、その直後に日本語を続ける場合は、`**語句**（補足）です。`のように記号を強調の外へ出します。文中で補足も含めて強調する場合は、`<strong>語句（補足）</strong>です。`のように書きます。Markdownの区切り規則によって`**`が強調として認識されない場合があるためです（[CommonMarkの強調規則](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)）。
- `**`自体を説明する場合は、インラインコードまたはコードブロックで囲みます。`mise exec -- pnpm check`に含まれる`lint:mdx`で、下書きを含む全記事の本文に強調として認識されない`**`が残っていないか検査します。表示確認では、意図した語句だけが強調されていることも確認します。
- 見出しレベルを飛ばしません。
- リンクテキストだけでリンク先の内容を判別できるようにします。
- 画像には内容または目的を表す代替テキストを付けます。
- MDXで利用できるReactコンポーネントは、共通マッピングに登録したものへ限定します。
- 出典が必要なコード、画像、文章には、ライセンスと参照元を記載します。
